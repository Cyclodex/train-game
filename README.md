# Train game

A browser train simulation. A grid of track tiles carries trains from depot to
depot, obeying signals and switchable junctions; a parallel road network carries
cars, trucks and buses through lane-aware junctions and over level crossings where
the two meet.

Built with Vue 3 + TypeScript on Vite. Everything the game draws — rails, roads,
lane markings, terrain, trees, rolling stock — is generated by code; the project
ships no image assets.

## Quick start

```bash
npm install
npm run dev
```

Then open http://localhost:5173.

## The three routes

| Route | What it is |
|---|---|
| `/play` | The game. Pick a mode, run the board, flip switches and hold signals. |
| `/editor` | The level editor: draw track and roads, place depots and signals, validate, export/import, hand a board straight to `/play`. |
| `/test` | A gallery of tiny maps, one per mechanic, drilled down `domain → category → scenario` and deep-linkable at `/test/:domain/:category/:scenario`. |

`/test` is the fastest way to understand any single feature: a mechanic on a
three-tile map is far easier to reason about than the same mechanic inside a full
level. Every feature in the game has a scenario there.

## How it fits together

The game is split in two, and the split is the reason it stays stable.

**An authoritative, headless simulation** (`src/sim/`) — plain TypeScript, no Vue
and no DOM. It owns game state and advances on a deterministic `step(dt)` tick.
Trains move as `(segment, progress)` along a graph, with acceleration and braking
derived from their mass, and **path reservation**: at a signal a train claims the
whole route to the next signal and enters only if every tile of it is free.
Collisions are impossible by construction rather than by collision detection. A
second vehicle simulation (`src/sim/road*.ts`) runs alongside on the same tile
topology, carrying road traffic with lane changes, overtaking, junction
arbitration and timed traffic signals.

**A thin renderer** — Vue components plus a `requestAnimationFrame` loop in
`src/game.ts` that ticks the simulation and writes the sampled positions straight
to the DOM. The renderer draws the current state and decides nothing.

**Tiles are data.** A cell is `{ connections: PortPair[], road?: Lane[], terrain?,
role?, signals? }`, where `connections` are unordered port pairs over
N/E/S/W/Centre. The tile's kind, its rail geometry and the simulation's routing
are all *derived* from those connections by one module (`src/tiles/`) that both
the simulation and the renderer import — so topology is defined exactly once.

A world is as big as its content: the grid follows from the level's own tile
coordinates, and a shared camera (drag to pan, scroll to zoom) moves a window over
a board rendered at its native tile size.

## Layout

```
src/
  sim/        headless simulation: trains, roads, signals, physics, objectives
  tiles/      the tile model — connections, geometry, lanes, validation, procgen
  modes/      game modes (puzzle, tycoon, network, citizens, sandbox — plus the
              unregistered daily board source and time-attack puzzle variant)
  components/ tile, train, crossing and HUD views
  views/      PlayView, EditorView, TestView/TestStage
  levels/     the default board and the /test scenario registry
  utils/      procedural art, colour assignment, coordinate helpers
tests/        unit (vitest) and e2e (playwright)
scripts/      screenshot, render probe and browser-install tooling
```

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Dev server at http://localhost:5173 |
| `npm run build` | Type-check (`vue-tsc`) and build to `dist/` |
| `npm run preview` | Serve the production build |
| `npm run test:unit` | Unit tests |
| `npm run test:e2e` | End-to-end tests in a real browser |
| `npm run browsers` | Install the Playwright browser builds (once per machine) |
| `npm run probe` | Render-level audit of every `/test` scenario in a real browser |
| `npm run shot -- <scenarioId>` | Screenshot a scenario |
| `npm run lint` | ESLint with `--fix` |

`.npmrc` sets `ignore-scripts`, so Playwright's browsers are not downloaded
automatically — run `npm run browsers` once before `test:e2e` or `shot`.

`npm run build` is the quickest correctness gate. `npm run probe` sits between the
unit tests and the eye: it opens every scenario in a browser and checks that each
tile lands in the grid cell its coordinate names, that no lane seam is painted as
a mismatch, and that nothing logs an error.
